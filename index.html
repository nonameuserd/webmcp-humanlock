    Developer view How WebMCP makes this possible Each lock registers exactly one WebMCP tool. When the lock changes, the available agent capability changes with it.

    Each lock calls document.modelContext.registerTool(). The agent discovers it via getTools() or toolchange, calls it with structured args, and the page mutates shared DOM state. Human and agent see the same vault. Neither can cheat: tools validate inputs and locks judge deterministically.
